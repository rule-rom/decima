# Общая VSB и выходная BUS16

В Decima-8 существуют две разные плоскости, которые нельзя смешивать.

| Плоскость | Направление | Назначение |
| --- | --- | --- |
| `VSB_INGRESS16[8]` | Conductor → swarm | Один общий входной кадр для всех ACTIVE-тайлов |
| `BUS16[8]` | swarm → Conductor | Насыщенная сумма вкладов разрешённых `BUS_W`-тайлов |

## VSB: общий физический контекст

VSB не проходит через цепочку тайлов. В пределах такта один и тот же восьмилинейный вектор доступен каждому ACTIVE-тайлу. Разные тайлы слышат его по-разному из-за своих весов и накопленной истории.

Именно это соответствует гидравлической модели: общий коллектор давления действует на множество локальных камер одновременно.

## BUS16: readout, а не вход тайла

В WRITE-фазе разрешённые тайлы вносят `row_out`:

```text
bus_raw[lane] = sum(row_out[t][lane] for eligible BUS_W tiles)
BUS16[lane] = clamp15(bus_raw[lane])
BUS_CLIP[lane] = bus_raw[lane] > 15
```

Верхняя граница `bus_raw` зависит от числа реально активных писателей. Старое значение `256 × 15` не является инвариантом v3: runtime поддерживает ткань до 4096 тайлов.

## Что означают BUS_R и BUS_W

- `BUS_R` — историческое имя флага корня. В текущем runtime он делает тайл seed графа ACTIVE; данные BUS16 тайл не читает.
- `BUS_W` разрешает вклад тайла в общий выход при наличии locked-источника в его ветви.

Локальное ребро соседства также не переносит Level16. Оно только разрешает потомку применить собственную матрицу к общему VSB на следующем такте.

## Почему разделение важно

Один поток данных предъявляется всей ткани, а топология выбирает, какие части личности имеют право отозваться. Благодаря этому глубина ветви выражает последовательность условий во времени без копирования рыночной, звуковой или сенсорной ленты между тайлами.
